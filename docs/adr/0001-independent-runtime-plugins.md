# 独立运行时插件根与显式启动协议

依据 ROADMAP 2026-10-07 的 M3.5 决策，游戏运行时改为固定版本的 CordiSharp 核心装配，每局使用独立根、服务及资源生命周期；编辑器继续使用自己的插件目录与根，通过公开会话契约访问运行时。这取代 M2.5 的“CordiSharp 仅限编辑器”限制，同时保留 C# 权威算法和 Lua／WASM 沙箱，避免将 UI 生命周期或编辑器依赖带入独立 Player。

游戏包通过 `game.start.json` 显式选择获准插件与唯一的定义加载器，包身份及能力配置不再分散在定义文件中。采用显式迁移而非自动旧格式回退，代价是旧包须转换并重打包，收益是目录、包、快照和录制能验证同一运行身份；旧记录仅由明确的历史接口处理。详情见 [运行时协议与兼容矩阵](../runtime-plugins.md)。

插件按权威、规则、CPU、扩展、本地会话、记录和定义加载等完整能力拆分；必需能力及依赖图在启动前验证，对局中不热卸载插件。生命周期交给 CordiSharp，规则执行顺序由会话显式确定。公共定义是数据，`LoadedModule` 的旧字段保留为现有消费者的兼容适配，进入新会话时校验两种表示一致。包不能激活任意原生 DLL；新增获准实现需要引擎发行更新。

## 小核心与默认桌游组合补充（2026-10-29）

2026-10-31 扩展：获准目录允许宿主显式导入带完整清单、实现及依赖的 .NET 运行插件，不再要求所有新增实现通过更新引擎发行获得。`PluginStore` 以精确版本、API、清单指纹和文件锁管理活动实现；游戏只选择身份，不能提供任意程序集路径。普通宿主受控动态加载，原生发行通过构建期 Reference 和静态工厂装配；两者复用能力、内容身份及生命周期校验，不承诺运行中热替换。`aot.compatible` 只准入，严格编译与目标环境验证仍必需。渲染后端属于图形宿主，同宿主只选一个；选择 GL 不改变 update／render 契约。首轮支持矩阵及尚未完成的联合验收见 [发布说明](../native-publication.md)。本补充覆盖下文旧有“不承诺 GL、NativeAOT 或任意外部运行插件”的阶段性边界，但不意味着任意第三方实现已被验证。

依据 ROADMAP 2026-10-24 的决策，上述权威、规则、席位和记录必需约束现由桌游定义提供者声明；不再施加于所有内容。Application.Core 只依赖通用契约及 CordiSharp，BoardGame.* 和原 Runtime 兼容门面保留桌游语义。规则的事务、随机、可见性及记录顺序不变；通用内容使用独立载荷和 format 3 包，桌游 format 2 保持显式适配。

初始化依赖图与 update／render 回调顺序图分别验证。图形宿主拥有设备，运行实例拥有唯一 update 驱动，视口拥有只读 render；每层使用独立根及显式父能力。准备阶段允许异步工作，成功后在安全边界发布状态；取消和故障不发布迟到结果。Headless 省去设备与绘制实现，仍校验所选插件身份。Player、Editor 和批量宿主通过共同契约驱动，不在 UI 事件订阅中决定规则次序。

桌游展示显式选择 board.render，旧工程必须主动迁移；不会因为游戏名称或缺项补插件。代价是迁移改变内容指纹，旧录制须保留原快照；收益是规则、交互、展示及纯接口能力可分别替换，无桌游安装组合无需携带 Kernel／Lua／WASM。旧扩展按当前程序集和能力键重新构建，不承诺跨版本托管 ABI。

普通数据包与预编译 Player 由独立作者插件导出。此决策覆盖 WindowsDX 的普通发布，不承诺 GL、NativeAOT 或任意外部运行插件。接口、默认组合与最小实时样例见 [应用循环](../application-loop.md)，实际兼容证据见 [迁移矩阵](../validation/application-compatibility.md)。

## M4 宿主边界补充（2026-10-08）

独立 Server 仍通过 `GameRuntime.Load` 与 `PlaySession` 使用上述插件根；Networking 管理连接身份与投影时序，不装配第二套权威内核，也不让网络成为本地宿主的必需依赖。Server／NetworkClient 均不引用编辑器或渲染层。

传输采用 HTTP 请求与完整投影快照，避免把权威命令日志发给远程客户端。回环允许 HTTP，跨机要求 HTTPS；房间密钥仅控制加入资格，席位 bearer 凭据单独控制操作和恢复。恢复令牌保留稳定值以容忍重连回执丢失，但使用首次签发起算的绝对有效期；每次恢复轮换连接令牌。代价是过期后无法再恢复该席位，且有效期内的 bearer 泄漏仍须由宿主结束会话处理。完整规则见 [联机说明](../networking.md)。

权威记录采用仅限宿主访问、无自动赛后公开的策略，授权边界是服务器进程和记录目录的操作系统访问权限；远程协议只提供身份投影记录。新增远程管理员或赛后公开接口需要另行定义授权需求，不能从普通玩家身份推导权限。

## 资源池与加载插件（2026-10-08）

资源读取同样使用运行时内置插件。基础 `resources` 提供唯一资源登记服务和原始文件加载器；`resources.images` 与 `resources.texturepacker` 依赖该服务并登记各自加载器，注册随 CordiSharp effect 释放。资源来源由启动配置显式声明文件、目录或目录加通配符，不根据 JSON 内容猜测格式。定义加载插件不承担资源格式解析。

加载操作先构建候选资源池，全部成功后发布不可变、可序列化、与图形设备无关的 `ResourcePool`。单图和图集都产出命名图片描述；源字节只按路径存放，图集描述包含裁剪、旋转和原画布信息。视图和打印只消费描述，GPU 纹理仍由每个视口管理。快照保留完整资源载荷并从载荷重建校验，不能依赖原始目录。此改动要求旧资源声明显式迁移、旧资源快照重新生成，换取加载、打包和回放一致的格式边界。
