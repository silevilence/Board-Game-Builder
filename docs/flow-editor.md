# 流程可视化创作

流程设计由可选 Editor 插件 `author.flow` 提供，运行游戏只需要独立的 `flow` 运行插件。
脚本契约与运行规则见 [流程作者说明](author/flow.md)，实现与验收以 ROADMAP 为准。

## 从工程到流程

1. 打开工程，在现有布局、实体与资源面板准备区域和稳定标识。
2. 启用“流程设计”，点击“打开流程设计”。已有 `flow` 配置的工程按入口指定的路径读取。
3. 尚无流程时使用“新建流程（替换 Lua/命令规则控制器）”：创建新的 JSON 文件、设计文件，
   并将 `game.start.json` 中的 `lua.rules`／`rules.commands` 切换为 `flow`。原脚本文件保留。
   此跨文件操作可以撤销；已有流程不会被覆盖。不提供旧规则自动转换。
4. 点击四种节点按钮创建节点；拖动节点，点击右侧命名结果端口，再点击目标左侧输入端口。
   允许回边、自环、多出口和多个结束节点。空白处或中键／右键拖动平移，滚轮缩放。
5. 选择节点或连线，编辑共享契约 JSON 并“应用属性”。Delete 删除选中节点及关联边，或删除连线。
   文档 Undo／Redo 同时恢复图与位置。修改显示名称不会改变节点 ID。

## 属性、脚本和草稿

属性 JSON 使用 Runtime 的 `FlowNode`／`FlowEdge`，面板附带字段类型与简要契约。
玩家节点 `seat` 可选择固定席位、当前席位或 Lua；静态 `actions` 或成对的
`actionsScript`／`decideScript` 配置动作，`complete=false` 表示继续等待。
结束节点 `winners=[]` 表示平局。边配置命名结果、条件、优先级与默认出口。

选择节点后，可按 execute、seat、actions、decide 创建最小 Lua 模板并同时关联。
已有文件通过属性里的 `{path,entry}` 关联，在下方工程 Lua 文件控件中编辑；同一控件也在
“Lua 脚本 / 工程 Lua 文件”提供。动态席位模板返回稳定席位 ID，不使用画布坐标。
Lua 中按运行契约读写实体、容器、区域；任意脚本中的引用无法靠静态检查穷尽，需结合试玩诊断。

无效属性、尚未应用的名称和脚本文件草稿属于工作区，关闭面板或重载插件不会丢失。
字段基线变化时拒绝覆盖，保留输入供合并；JSON／YAML 同时修改同一文件时也拒绝覆盖。
外部磁盘修改通过“外部编辑与连接”协调。保存、试玩、导出前需要应用或放弃未应用字段。
流程语义文件允许暂时结构无效并继续编辑，但运行／导出必须通过校验；不可运行的结构
不能通过当前文档的正常保存验证。原始语法损坏时可转到“游戏文件”修复。

流程文件旁的 `<流程路径>.design.json` 保存位置、显示名称、缩放和平移。
它不被运行入口引用，不进入流程载荷，也不改变运行身份。不要手动将它配置为运行资源。
流程支持独立于主定义作者格式：例如 `definition.state` 工程可使用流程设计，
不会因此自动获得模块配置等其他格式专用面板。

## 校验与试玩

问题列表和画布标记复用 CLI 的共享校验，点击问题定位节点或连线。
`error` 阻止运行；`warning` 提示不可达内容、恒假出口；`info` 说明依赖局面或 Lua 的
条件仍需作者负责终止性。封闭循环涉及的所有无法到达终局节点分别列出。
显示的校验版本对应当前已应用内容；未应用字段会明确提示且不被当作已经验证。

“重开流程试玩（作者）”使用基础 sessions 能力，真人／CPU 在“试玩与调试”配置。
作者视图显示实际节点、等待席位、命名结果、出口和最近 64 条轨迹；普通席位投影不显示
私有流程上下文或作者轨迹。点击轨迹定位脚本所属节点；错误和预算暂停显示运行诊断。
仅预算耗尽、取消／恢复边界或显式暂停可“显式继续”，脚本错误须修复后重开。

运行快照与当前工程内容不同，或尚有未应用字段时，关闭高亮并要求显式重开。
纯视图调整不影响匹配。面板重建只重新订阅会话，不重新发牌或执行系统节点。
停止／卸载流程设计插件不会销毁基础文档与会话；停止试玩使用明确的停止命令。

## 独立导出

在“独立导出”选择正式 self-contained Player 发行目录和新输出目录。
“依赖预检”和“导出当前草稿的独立游戏”消费固定来源版本，不隐式保存源工程；
结果显示来源版本，导出期间的后续编辑不会混入已经捕获的快照。
输出通过 `Play.exe` 运行，携带游戏流程与脚本，不携带 Editor 功能插件。

自动验收入口：`Editor.exe --verify-flow <新结果路径.json>`；输出同名 `.png` 和 `.project`
工程。它使用已有卡牌示例的实体／短脚本夹具，通过真实 Avalonia 按钮、属性编辑、指针拖动
和端口点击重新构建流程，并运行两类席位模式、预算暂停、保存重开与生命周期验证。
证据与具体环境见 [验收记录](validation/flow-editor-review.md)。
