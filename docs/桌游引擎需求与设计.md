# 桌游引擎需求与设计

版本：0.1  
状态：草案  
配套决策：C# 内核 + Avalonia 编辑器 + MonoGame / Veldrid 画面；玩法脚本化；编辑器插件化借鉴 Cordis 生命周期，不引入 Cordis 运行时。

---

## 1. 背景与目标

### 1.1 问题

RPG Maker、Shooting Game Builder 能做成「套模板即可出游戏」，是因为目标类型骨架稳定。桌游规则差异极大，共用的不是玩法，而是媒介：

- 组件、区域、容器、正反面
- 可见性与归属
- 回合 / 阶段骨架
- 随机、日志、联机一致性

现有工具分别停在不同层：Tabletop Simulator 管桌子，VASSAL 管棋子 Trait，BGA / boardgame.io 管合法操作。本引擎取 VASSAL 的模块化方向，但把边界画得更干净：媒介预置为配置与插件，玩法保留脚本。

### 1.2 产品目标

做一款桌游专用引擎 + 可视化编辑器，使作者：

1. 用配置组合桌面媒介（棋子、卡牌、牌库、手牌、网格、骰子、计分）。
2. 用脚本实现具体规则（合法操作、计分、胜负、例外）。
3. 在编辑器内直接试玩、单步命令、热重载脚本。
4. 导出独立可运行程序，玩家无需安装编辑器。

成功标准不是「不用写脚本也能做卡坦」，而是：做卡坦时，桌子、手牌、骰子、同步、隐藏信息全部不用自实现，作者只写发资源和建造等规则脚本。

### 1.3 非目标

- 不做「桌游版 RPG Maker」：不预置工放、卡组构筑、区域控制等玩法模板为内核。
- 不做 3D 物理沙盒。物理若需要，作为后续表现层，不进入 Kernel。
- 不做通用游戏引擎。不为平台跳跃、动作、开放世界服务。
- 第一年不做第三方插件市场、用户 C# 热加载商店。
- 导出不以「为每个游戏生成 C# 工程再编译」为主路径。
- 不引入 Cordis / CordiSharp 作为运行时依赖。只借鉴其插件生命周期思想。

## 2. 设计原则

1. **模块化的是媒介，不是类型。** 概念换一个完全不同的游戏仍然存在，才进内核或官方组件；否则进脚本。
2. **命令进、状态出。** 一切状态变化都是可序列化命令。脚本只能提议、拦截、改写、补发命令，不能直接改字段。
3. **结构合法 ≠ 规则合法。** Kernel 拦结构（对象不存在、看不见、容器装不下）。规则合法性一律脚本。
4. **可见性是内核，不是约定。** 手牌、扣牌、暗标、迷雾必须由权威端投影。客户端不得持有不该看见的真值。
5. **Editor 与 Player 共用同一 Kernel、同一 View、同一插件加载语义。** 禁止两套管线。
6. **壳固定，能力可插拔。** Kernel 不是插件容器。编辑器大部分功能以接口加载，且必须可逆卸载。
7. **媒介要厚，玩法要薄。** 官方提供完整桌面原语和示范脚本，不把玩法锁进内核。

## 4. 总体架构

### 4.1 逻辑分层

```text
玩法脚本（Lua）
    │  approve / reject / emit / query(投影后状态)
    ▼
Kernel
    命令日志 · 状态库 · 可见性投影 · 结构校验 · 随机
    ▲
    │ 注册组件类型 / 命令 / 吸附 / 容器
运行时插件（官方原生白名单 + 第三方 WASM）
    │
View（ITableView）
    渲染、输入、拖拽手感、音效
    │
Host
    Editor.exe 或 Player.exe
```

判断进哪一层：

| 问题 | 层 |
|---|---|
| 换游戏后这个词还在吗？手牌、翻面、牌库、回合 | Kernel 或官方组件 |
| 是不是新的媒介能力？三层棋盘、秘密出价箱 | 运行时插件 |
| 是不是这条规则？没有羊不能造镇 | 脚本 |
| 是不是编辑器里的面板 / 导入器 | 编辑器插件 |

### 4.2 程序切分

三个可分发单元，代码上是多个程序集：

```text
src/
  Kernel.Abstractions/     命令、实体、组件接口、脚本回调。零 Host 依赖
  Kernel/                  命令总线、状态、模块加载。可依赖 JSON 等 BCL 级库
  Script.Lua/              实现 IScriptHost
  Plugin.Wasm/             运行时插件沙箱
  View.Abstractions/       ITableView，不引用具体渲染
  View.MonoGame/           或 Veldrid。Editor / Player 共用
  Player/                  薄 Host：窗口 + Kernel + View + 运行时插件
  Editor/                  Avalonia 壳：文档、Undo、PlaySession、布局
  Editor.PluginHost/       ALC + 可逆 IEditorContext
  Editor.Plugins.*/        官方面板，全部 editor_only
```

依赖只能向下：

```text
Editor → Editor.PluginHost → Kernel → Kernel.Abstractions
Player → View.* → Kernel → Kernel.Abstractions
```

禁止 Editor 与 Player 互相引用。共享逻辑只放 Kernel / View。

「Kernel 无内部依赖」定义为 **无 Host 依赖**，不是零 NuGet。禁止依赖 Avalonia、渲染、插件管理器 UI、`AssemblyLoadContext` 业务化。允许 BCL、`System.Text.Json`、日志抽象。

### 4.3 同一运行时、两种宿主

```text
editor.exe  ──打开模块──►  编辑数据
                 │
                 │ Play
                 ▼
            IPlayHost  ──►  Kernel + View + 脚本 + 运行时插件

player.exe ──打开同一模块──►  同一个 IPlayHost
```

Play 两种都要，调试协议必须同一套：

- **进程内 Play**：编辑器面板起 `PlaySession`，热重载快。
- **独立 Play**：`player.exe --module <path> --debug`。崩溃不带走编辑器，二进制与导出版一致。

调试能力挂在 `PlaySession` 上，不挂在编辑器窗口上：暂停、单步命令、监视隐藏信息、重放日志、热重载脚本。导出版同一代码，仅 UI 关闭。

## 5. Kernel 设计

### 5.1 原语（P0 必须齐）

1. Entity + 数据组件  
2. Zone / Container / Hand  
3. Command + 日志 + 回放  
4. Visibility projection  
5. Seeded RNG  
6. TurnClock（玩家顺序与阶段空壳，不含玩法）  
7. 脚本沙箱接口（approve / reject / emit / query）  
8. 模块包加载：配置 + 资源 + 脚本 + 可选运行时插件  

有这 8 个，卡牌、战棋、工放都能做。缺的是组件插件和编辑器，不是新架构。

### 5.2 命令

脚本与 UI 都不直接写对象字段。所有变化成为命令，例如：

```text
Move(piece, to)
Flip(piece)
Draw(from, to, n)
Reveal(piece, toPlayer)
Roll(die)
SetProp(piece, key, value)
PassPriority
```

内核保证：

- 命令可序列化、可回放、可联网
- 随机可复现
- 可见性不可被脚本绕过
- 客户端只能提议，权威端才提交

状态 = 初始局面 + 命令序列。回放、观战、反作弊、断线、教程都由此导出。

### 5.3 组件（配置化，无序数据，不对顺序敏感）

棋子 = 实体 + 一组数据组件。禁止 VASSAL 式对顺序敏感的装饰器链。

官方 P0 组件：

| 组件 | 配置声明 | 明确不包含 |
|---|---|---|
| Location / Snap | 位置、吸附网格 | 这格能不能建造 |
| Stackable / Container | 可叠、可进袋 / 牌库 | 抽到的牌怎么打出 |
| Faces / Hidden | 面数、谁能看 | 何时必须亮出 |
| Owner / Hand | 归属、是否手牌 | 手牌上限 |
| Deck | 洗、抽、底牌 | 每回合抽几打几 |
| Grid | 六角 / 方格 / 自由 | 控制判定、供应线 |
| TurnClock | 玩家顺序、阶段名单 | 阶段内具体动作 |
| Counter | 数值、上下限 | 数值如何结算 |

原型系统：先定义「步兵 = Move(1) + Flip + Stack + Owner」，再实例化。原型是数据，不是继承树。

### 5.4 脚本 API（窄而完整）

脚本是规则层的正式接口，不是逃生口。

能做：订阅命令、拒绝命令、派生命令、查询投影后状态、声明当前阶段可用动作、判定结束与分数、指定下一位玩家。

不能做：偷看隐藏信息、跳过权威校验改状态、改网络 / 存档格式、在客户端本地「先当它合法」、自造 `math.random()`。

配置挂脚本入口，例如：

```yaml
piece: Knight
components: [Location, Faces, Owner, Stackable]
hooks:
  canMove: scripts/knight.lua#canMove
  afterMove: scripts/knight.lua#afterMove
```

语言：Lua。热重载必须有。不采用 C# 作为玩法语言，以免 AOT / 导出 / 沙箱一并恶化。

### 5.5 TurnClock

只提供「现在是谁、现在叫什么阶段、是否同时行动、优先级如何传递」。  
不提供「抽取阶段必须抽一张」。阶段能做什么由脚本声明。

## 6. 插件体系

插件解决「内核没预置这种媒介或编辑器能力」，不解决「这个游戏有特殊规则」。规则不是插件，是 VM 中的脚本。

### 6.1 从 Cordis 借鉴什么，不借鉴什么

借鉴：

- **可逆副作用。** `Activate` 注册的服务、事件、UI、快捷键，必须在 `Deactivate` 时全部交还。卸插件不能留幽灵面板。
- **声明式依赖。** 插件声明 `provides` / `requires`。被依赖者重载，依赖者跟着拆再建。
- **共享 Context，禁止满地单例。** 编辑器能力通过 `IEditorContext` 取得。
- **按宿主分流。** 同一清单字段区分 Editor / Runtime；导出物理删除 `editor_only`。

明确不采用：

- Cordis / CordiSharp 运行时，以及 Node / TS 宿主。
- 「一切皆插件」，包括 Kernel 本身、文档模型、Undo、PlaySession、插件加载器、主窗口壳。
- 把可逆 DI 做进 Player。Player 只热重载脚本，运行时插件按模块加载，不在对局中热卸。
- 用特性扫描组装的 MEF 作为主加载器。

### 6.2 三条车道

| | 编辑器插件 | 运行时插件 | 规则脚本 |
|---|---|---|---|
| 谁写 | 扩展编辑器的人 | 扩展媒介的人 | 做一款桌游的人 |
| 例子 | 检视器、TTS 导入、拼版 | 新组件、新六角几何、拍卖 UI | 没有羊不能造镇 |
| 可信度 | 本机、半可信 | 官方原生白名单 / 第三方沙箱 | 默认不可信 |
| 热重载 | 必须可逆卸载 | 换模块时加载，对局中不热卸 | 必须热重载 |
| 崩溃 | 原生可打死编辑器 | WASM 隔离；原生可打死进程 | 只弄坏这一局 |
| 导出 | 全部剥离 | 打进 Player / 模块 | 打进模块 |
| 技术 | C# ALC | WASM 默认，官方可用 ALC | Lua |

脚本可以调用插件注册过的组件，不能加载插件。否则权限被绕开。

加载顺序固定：

1. Kernel  
2. 官方原生运行时插件  
3. 模块依赖的 WASM 插件（校验 API 版本）  
4. 模块脚本  

### 6.3 编辑器插件宿主

壳固定、功能插件化。自写小宿主，不引入元框架。核心接口：

```csharp
public interface IEditorPlugin
{
    PluginManifest Manifest { get; }
    void Activate(IEditorContext ctx);
    void Deactivate();
}

public sealed class PluginManifest
{
    public string Id { get; init; } = "";
    public Version Version { get; init; } = new(1, 0, 0);
    public Version Api { get; init; } = new(1, 0, 0);
    public PluginKind Kind { get; init; }
    public string[] Provides { get; init; } = [];
    public string[] Requires { get; init; } = [];
}

public enum PluginKind
{
    Editor,
    Runtime,
    Content
}
```

加载：`AssemblyLoadContext` + `AssemblyDependencyResolver`（可薄封装 McMaster.NETCore.Plugins）。

`IEditorContext` 提供可撤销注册：

- `Views` 工具面板  
- `Inspectors` 组件检视器  
- `Importers` 资源导入  
- `Commands` 菜单 / 快捷键  
- `Services` 共享服务  

`Activate` 返回或登记 `IDisposable`；`Deactivate` 全量释放。B 依赖 A 时，A 停用必须先停 B 再停 A，再按依赖重建。这就是 Cordis 生命周期在 C# 里的等价物。

**必须插件化：** 检视器、导入器、工具面板、调试页、导出附加步骤、运行时组件对应的编辑器 UI。

**必须留在 Host 骨架：** 模块打开关闭、Undo、PlaySession、插件加载器本身、主布局壳。无插件时编辑器仍能打开空模块，而不是白屏。

### 6.4 运行时插件

默认 WASM（Wasmtime）。一份字节码同时进编辑器和 Player，跨平台，内存隔离。

仅官方重能力发原生插件（C# ALC）：必须碰渲染、平台窗口、高性能导入的部分。

清单为数据：

```yaml
id: hex-grid
version: 1.4.0
api: 1
kind: runtime
entry: hex_grid.wasm
permissions:
  - register_component
  - register_snap
```

Kernel 只开放窄能力：注册组件类型、注册命令、注册吸附 / 容器、注册导入器。  
不开放：读隐藏状态、写文件系统、直接改内存、发网包。需要这些就不叫插件，叫改内核。

模块声明依赖，例如 `hex-grid >= 1.4`。Player 启动时解析，缺了就失败并说明，禁止静默退化。

### 6.5 官方组件与第三方扩展的关系

第一年：官方组件全部是配置，写在 Kernel 或官方运行时库里，不走第三方加载器。第三方只能交 WASM，规则只能交 Lua。模块格式和命令集稳定后再考虑开放原生插件。

不预置「欧式经济插件」「卡组构筑插件」。示范模块可以展示这类玩法，模板活在示例里，不活在内核里。

## 7. 编辑器与画面

### 7.1 编辑器

Avalonia 桌面程序。嵌入 View 控件作为桌子预览与 Play 视口。

主工作区：

- 模块资源树（组件原型、牌库、地图、脚本、插件依赖）
- 桌子 / 地图视口（同一 View）
- 检视器（由插件提供，按选中组件切换）
- 命令时间轴 / 日志
- 脚本编辑与错误输出

Play 工具条：进程内 / 独立 Player、暂停、单步、显示隐藏信息（仅调试且需明确身份）。

### 7.2 画面

View 是 Host 的适配器，不是 Kernel 的一部分。Kernel 输出「桌子上有什么、当前玩家能看见什么」；View 负责精灵、拖拽、叠牌手感、音效。

P0 用 2D 即可。MonoGame 或 Veldrid 二选一作为第一实现；`View.Abstractions` 挡住选择，换渲染器只换实现。

不把节点树当作规则模型。拖拽在 View 产生「意图」，翻译成命令再进 Kernel；Kernel 拒绝则 View 回弹。

## 8. 模块格式与导出

### 8.1 模块是数据

```text
MyGame.bgm          # 打包格式；开发期可以是目录
  module.yaml       # id、版本、依赖插件、入口脚本
  components/       # 原型与实例
  zones/
  scripts/
  assets/
  plugins/          # 仅 runtime，通常 wasm
```

开发期以目录加载，导出时打成单一模块包。编辑器 Play 与 Player 都走同一加载器。

### 8.2 导出：固定 Player + 模块包（唯一主路径）

```text
MyGame/
  Player.exe
  Player.dll          # Kernel + View + 官方运行时
  data.bgm
  plugins/            # 模块声明的 runtime 插件
```

导出是拷贝官方 Player 发行物 + 打包模块 + 解析运行时依赖。作者机器不需要 SDK。

Player 的发布配置（单文件、RID、将来 AOT）是引擎产品流水线，不是每个桌游一份 csproj。AOT 时 Lua / WASM 仍是数据；这也是玩法不用 C# 的原因。

### 8.3 明确不做的导出

不为每个游戏生成临时 C# 工程再 `dotnet publish`。那会变成第二产品：SDK 探测、RID、AOT、两套管线、MSBuild 错误面向作者。Editor Play 走动态加载、导出走生成工程，加载顺序与内容根路径必分叉。

原生插件需要 AOT 进自定义 Player 时，作为开发者高级工作流，不进「导出游戏」默认按钮。

导出产品形态：

```text
Export
 ├─ Debug Play      同一 Player.exe + 松散模块目录
 ├─ Release Pack    同一 Player.exe + data.bgm
 └─ Store Player    官方预编译 / AOT 的 Player 发行物 + data.bgm
```

## 9. 技术选型

| 点 | 选择 | 说明 |
|---|---|---|
| 语言 | C# | 编辑器、内核、序列化、ALC 一致 |
| 编辑器 UI | Avalonia | 真桌面软件，可嵌游戏视口 |
| 渲染 | MonoGame 或 Veldrid，先 2D | 经 View.Abstractions 隔离 |
| 内核 | 纯 C# 库 | 无 UI / 渲染引用 |
| 玩法 | Lua | 热重载、可沙箱、导出友好 |
| 第三方运行时插件 | Wasmtime | 一份字节码，编辑器与 Player 通用 |
| 官方重插件 | AssemblyLoadContext | 仅白名单 |
| 编辑器插件 | 自写可逆宿主 + ALC | 借鉴 Cordis，不引用 Cordis |
| 导出 | 固定 Player 动态加载模块 | 见第 8 节 |
| 不选 | Unity / Unreal / 从 OpenGL 自研 / 以 Godot 为产品壳 | 授权、形态或重复造轮子不符合本产品 |

若需加速验证，可用 Godot 4 临时代替 Editor 壳与 View，但 Kernel 仍按本文独立；正式产品形态仍是 Avalonia + 自有 Player。

## 10. 权限、安全与联网（约束）

- 脚本查询永远走投影。调试器看隐藏信息必须选择身份，且仅限本地调试。
- 运行时 WASM 默认权限为空，按清单授予 `register_*`。无 `fs`、无 `net`、无 `read_hidden`。
- 联网以命令日志为传输单位，不以场景图为传输单位。权威在 Host 一侧（先本地权威，再独立服务器）。
- 模块来源与插件哈希写入 `module.yaml`，后续可加签名；P0 不做完整安全模型，但 API 不得阻止日后加上。

## 11. 分期

### M0 骨架（先证明不倒）

- Kernel.Abstractions + Kernel：实体、少量组件、命令日志、投影、种子随机
- Lua：`on Move` 可 reject / emit
- 无编辑器：命令行 Player 加载目录模块，控制台打印状态
- 验证：一副牌、抽、翻、手牌对玩家 B 不可见、回放一致

- View 2D、拖拽变命令
- Avalonia 编辑器壳：打开模块、检视器、进程内 Play
- 编辑器插件宿主：至少一个官方检视器作为插件加载、可停用还原
- 导出 Release Pack：Player.exe + 目录 / bgm

### M2 作者能做完整单机模块

- 官方组件齐：Deck、Hand、Grid、TurnClock、Dice、Counter、Prototype
- 独立 Player Play 与进程内 Play 命令日志一致
- 示范模块两份：简单卡牌对战、简单六角战棋
- 脚本热重载、命令单步

### M3 可扩展

- Wasmtime 运行时插件：第三方注册一个组件
- 导入器插件
- 热座与基础联机（命令同步）
- 模块依赖解析与缺失报错

### 刻意后置

物理 3D、玩法模板市场、用户 C# 插件商店、按游戏生成工程、Cordis 兼容层、VASSAL 模块导入（若做，作为编辑器导入插件，不反向污染 Kernel）。

## 12. 风险与冻结决策

| 风险 | 对策 |
|---|---|
| Editor 与 Player 分叉 | 共用 Kernel / View / IPlayHost；独立 Play 使用真 Player.exe |
| 把规则做成可视化编程 | 复杂规则只写 Lua；触发器只做示范，不作为主语言 |
| Trait 顺序地狱 | 无序数据组件 + 固定系统顺序 |
| 一切皆插件导致无内核 | Kernel 八原语不可卸载 |
| 引入 Cordis 导致双运行时 | 只保留可逆注册与依赖重建思想 |
| 导出变成代码生成 | 主路径永远是固定 Player + 数据模块 |
| 过早开放原生第三方插件 | 第一年 WASM + Lua；原生仅官方 |

已冻结、后续文档不得静默推翻：

1. Kernel 无 Host 依赖；Editor / Player 共用 Kernel。  
2. 命令日志是第一公民。  
3. 可见性在 Kernel。  
4. 玩法 = Lua；第三方运行时扩展 = WASM。  
5. 编辑器插件可逆，壳不可插件化。  
6. 导出 = 固定 Player 动态加载模块。  
7. 借鉴 Cordis 思想，不引入 Cordis 实现。
